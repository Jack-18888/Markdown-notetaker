# Workspace navigation

T08's [lifecycle client and helpers](../../apps/web/src/workspace/lifecycle.ts) provide validated create/update/delete requests, descendant counts, and destination choices excluding moved subtrees. Note mutations use loaded revisions; metadata-only changes omit content. Duplicate destination paths receive stable numbered labels while resource IDs remain their values. Sidebar controls create, rename, move, and delete notes/folders.

The [move dialog](../../apps/web/src/workspace/MoveDialog.tsx) uses full-path destination labels and offers the workspace root. It excludes the moved folder and its descendants, disables unchanged destinations, and leaves the picker and selection intact after server rejection. Successful moves preserve resource identity, reveal the new breadcrumb path, and omit note content from writes.

The [deletion dialog](../../apps/web/src/workspace/DeleteDialog.tsx) names the target, explains permanent deletion, and counts subfolders and notes from the current tree. The server deletes a folder's current subtree transactionally; counts are a preview, not a version lock. Cancel receives initial focus. Note deletion uses the opened revision and rejects a newer saved version until it is reviewed. Failed deletes preserve the dialog and selection; committed deletes reveal the parent folder or workspace root. There is no trash or undo.

[Name dialogs](../../apps/web/src/workspace/NameDialog.tsx) create notes/folders in the selected folder (or the selected note's folder) and rename the selected resource. [Native modal dialogs](../../apps/web/src/workspace/Modal.tsx) make the background inert, label their headings, preserve keyboard traversal, and restore focus on cancellation. Pending title drafts block lifecycle actions. Note actions wait for loaded note metadata so revision checks correspond to what was opened.

The [operation state](../../apps/web/src/workspace/useOperation.ts) blocks concurrent submissions and pending dismissal. Failed mutations keep field values and existing tree/selection. Once a mutation returns a committed result, only metadata refresh is retried; the write is not repeated. Closing after a failed refresh requests a separate workspace reload. Successful refresh applies a validated tree, reveals the selected resource's ancestor path, and reloads note detail after lifecycle changes. Pending writes install the tab-close warning. A network failure before a response can still leave its server outcome unknown; the API does not provide idempotency keys.

The [workspace client](../../apps/web/src/workspace/api.ts) loads tree metadata separately from note detail, checks shared runtime schemas, verifies note identity, and accepts only public error envelopes with matching HTTP statuses. Network/protocol errors use fixed user-facing messages. Reads disable browser caching and accept cancellation signals. The [app shell](../../apps/web/src/App.tsx) connects root/folder navigation and selected-note reading to this client.

The [hierarchy index](../../apps/web/src/workspace/tree.ts) rejects duplicate IDs, missing parents, and cycles before navigation renders them. It builds parent/child maps iteratively so validation does not recurse through deep folder paths. The root has a null folder ID; selection and expansion use resource IDs, never labels.

The [folder navigation](../../apps/web/src/workspace/FolderTree.tsx) uses nested lists, native buttons, explicit expansion state, and separate folder-selection controls. It marks the selected resource with `aria-current`. [Folder contents](../../apps/web/src/workspace/FolderContents.tsx) lists direct children and distinct empty-root/folder messages; [breadcrumbs](../../apps/web/src/workspace/Breadcrumbs.tsx) provide native buttons back to root and ancestors. Selection expands its ancestor path and focuses the main surface. A narrow-screen note selection closes the sidebar; the header can reopen it. Refresh retains a valid selection or shows root with a notice when that item is gone.

Reopening the sidebar resets its internal scroll, brings it into the viewport below the sticky header, and focuses the first navigation control. This remains reachable after scrolling a long note on narrow screens. The sidebar can be hidden without unmounting the selected note.

The [request lifecycle](../../apps/web/src/workspace/useLoad.ts) aborts superseded/unmounted loads and ignores their completions even if a transport does not honor cancellation. Each selected note mounts a separate keyed [note panel](../../apps/web/src/workspace/NotePanel.tsx). Loading, errors, and retry remain scoped to that panel; selecting another note never reuses the old note's loaded state. Metadata refresh and note-body requests are separate.

The lazy [reading view](../../apps/web/src/workspace/NotePreview.tsx) uses T06's conversion boundary and destroys the read-only editor on cleanup. Unsupported source or a failed preview module uses the safe source fallback. Checkboxes are disabled; there are no body writes on opening or navigation. Mermaid remains literal source until T10. The Markdown parser and preview have separate production chunks, loaded on demand. Body editing and autosave remain T09/T11.

[Title editing](../../apps/web/src/workspace/TitleEditor.tsx) is an explicit edit/save/discard flow. It validates the shared name rules and sends only title plus the loaded expected revision. A successful response updates note metadata without reloading the body or replacing a newer title draft. Failed/conflicting saves retain the draft; navigation and metadata refresh wait until changes are saved or explicitly discarded. In-flight writes cannot be discarded or submitted twice. A dirty/in-flight title installs a normal tab-close warning. This protects the current title workflow; T11 still owns general autosave, body snapshots, and conflict recovery.

Navigation ordering is folders first, then notes. Each group sorts by label using an English numeric, case-insensitive collator; ties use the original spelling and then the resource ID. This is a display policy, not a persistence order. Duplicate names remain distinct resources. Breadcrumbs follow parent IDs from root to the selected resource's folder.
