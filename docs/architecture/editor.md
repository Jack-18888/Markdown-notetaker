# Editing, saving, and conversion

## Rich editing

The [editor UI redesign](../../roadmaps/editor-ui-redesign.md) centers the title, compact toolbar, and prose in a roughly 66-character writing column. Instrument Sans, Spectral, and IBM Plex Mono are local font packages bundled into the frontend. Shared light/dark tokens follow the system theme across writing, navigation, dialogs, menus, code, source fallback, and recovery. Icon controls retain accessible names and visible focus. Layout and theme changes keep the same editor and save session, preserving drafts, selections, and undo history.

Breadcrumbs, save status, and Note actions stay in the sticky workspace header. Failed/conflicted saves link to focusable recovery controls beside the retained draft. The detailed failure is announced once as an alert; the compact header remains a status region. Mermaid previews use the current theme tokens and rerender on system-theme changes without changing diagram source or writing notes.

Code and diagram previews scroll within their blocks on narrow screens. Diagram previews retain a minimum canvas width so labels remain readable; the named preview is keyboard focusable for scrolling.

The writing interface uses open-source Tiptap 3.33.0 with `@tiptap/markdown`, chosen for extensible rich blocks and local Markdown conversion. The [extension configuration](../../apps/web/src/editor/extensions.ts) covers the release's rich blocks and marks, including nested tasks and a dedicated Mermaid node. Underline and automatic trailing paragraphs are disabled because they have no reliable source representation here.

[Schema/DOM fixtures](../../apps/web/src/editor/__test__/extensions.test.ts) verify supported block round trips and literal code/diagram rendering. Code fences grow to exceed any embedded backtick run. Application UI must use the [conversion boundary](../../apps/web/src/editor/markdown.ts) before loading external Markdown, rather than calling Tiptap's raw parser or Markdown commands directly.

T09's [shared commands](../../apps/web/src/editor/commands.ts) define block choices, formatting/history actions, searchable labels, and validated link changes for the [toolbar](../../apps/web/src/editor/EditorToolbar.tsx) and [slash menu](../../apps/web/src/editor/SlashMenu.tsx). They preflight eligibility before consuming a slash query because a failed Tiptap chain does not roll back earlier steps. Diagram insertion is restricted to top-level paragraphs or replacing the full document, matching the conversion policy. [Command tests](../../apps/web/src/editor/__test__/commands.test.ts) use the real editor schema to verify single-update mutations, safe serialization, undo/redo, and unchanged text/selection after rejection.

The [writing canvas](../../apps/web/src/editor/NoteEditor.tsx) mounts once per selected note, with a blank-note placeholder, inherited typing shortcuts, and fresh undo history. The slash menu filters paragraph-start queries, keeps focus in the editor for arrows/Enter/Escape, supports pointer selection, and leaves code, links, compositions, and rejected commands alone. The link dialog restores the selection and rejects unsafe addresses before changing marks.

Writing enables an optional [Mermaid node view](../../apps/web/src/editor/mermaid-node-view.tsx) without changing the conversion schema. Its [React view](../../apps/web/src/editor/MermaidView.tsx) updates the source attribute transactionally, supports editor undo/redo from the source field, and removes blocks as distinct undo actions. Source controls and scrollable previews have visible keyboard focus. Preview requests debounce for 350 ms, abort on source changes/unmount, and associate results with the exact requested source so an older result cannot replace a newer preview. Invalid/blocked/oversized diagrams retain editable, saveable source with an inline message. Rendering is bounded on the main thread; already executing synchronous layout cannot be interrupted.

The [per-note save coordinator](../../apps/web/src/workspace/SaveCoordinator.ts) replaces T09's separate explicit writes. It debounces title/body edits together, serializes immutable body snapshots only when submitting them, and sends one revision-checked request at a time. Only that snapshot becomes acknowledged; newer typing and undo history stay in the current editor. Title-only requests omit content. Failed serialization sends no write, and request failures retain the drafts. Ambiguous failed writes stay dirty even after undo until a revision-checked retry acknowledges the result.

The [source policy](../../apps/web/src/editor/source-policy.ts) checks Marked tokens without generating HTML. Tables, images, embedded HTML/comments, YAML/TOML frontmatter, reference definitions, math, extra fence metadata, NUL/BOM, mixed task/plain lists, and diagrams nested inside containers require source fallback. Unsafe links also require fallback. Ordinary fenced and inline code stay literal and are not inspected as markup. Rich conversion is limited to 128 KiB of UTF-8 source, 10,000 tokens, and nesting depth 32; larger valid API notes remain available as raw source. These limits constrain conversion, not stored Markdown or import limits.

The [source fallback view](../../apps/web/src/editor/SourceFallback.tsx) explains that the original Markdown is preserved and displays selectable source in a labelled, keyboard-focusable, scrollable block. React escapes the text; the view creates no links, HTML preview, or editable body. The [selected-note content view](../../apps/web/src/workspace/NoteContent.tsx) uses it for unsupported source and exposes no body-writing controls. [Fallback view tests](../../apps/web/src/editor/__test__/source-fallback.test.ts) verify literal hostile markup and accessible control names.

`loadMarkdown` returns either the untouched source plus a fallback reason, or a rich document with a guarded serializer. Fallback results expose no editable document or serializer. Rich results capture an immutable ProseMirror baseline separately from the caller's JSON. Unchanged documents serialize to their original bytes; changed documents must pass schema, link, size, and structural round-trip checks before yielding source. Failure throws a fixed `MarkdownConversionError`; callers retain their current editor and saved source. This boundary does not acknowledge saves or replace local editor state.

[Mermaid payload recovery](../../apps/web/src/editor/mermaid-source.ts) preserves top-level diagram strings before Marked normalizes line endings. Editing another block retains exact diagram text, including LF, CRLF, CR, trailing spaces/blank lines, invalid syntax, and embedded backticks. Unclosed diagram fences and unsupported container forms retain the original source in fallback. The [boundary fixtures](../../apps/web/src/editor/__test__/markdown.test.ts) verify source retention, guarded mutations, and exact diagram payloads after other body edits.

Saved content is raw Markdown. The frontend loads that source into the rich editor's internal representation and serializes edits back to Markdown. Editor trees remain frontend state; the backend stores the complete source string. See [the storage decision](../decisions/0003-raw-markdown.md).

Represent a diagram as a dedicated editor block containing plain Mermaid source. Frontend conversion hooks map that block to and from fenced `mermaid` Markdown. Parser and serializer fixtures must cover every supported block and mark before the writing interface relies on them.

Keep the original Markdown until the body is actually edited. Opening, previewing, renaming, moving, or exporting an untouched note must preserve its source, including line endings and whitespace. If the rich editor cannot represent a construct without losing content, retain the raw source and provide a safe read-only fallback instead of saving a reduced document.

## Save lifecycle

1. Load the selected note and its revision into the editor. Keep pending title/body changes locally.
2. After 750 ms without edits, queue a save. Serialize changed editor content to Markdown and writes per note; newer edits made during a request remain pending. Title/location-only changes omit content.
3. On success, acknowledge only the submitted snapshot and revision. An older response must not replace newer edits, undo a rename/move, or update a different selected note.
4. Before switching notes or discarding the active document, flush pending changes. If saving fails, retain the editor and offer retry.
5. On a revision conflict, retain local content until the user explicitly reloads or saves it as a new note.

Reset undo history between notes. A dirty-tab warning helps with ordinary closure; it is not crash recovery or version history.

The [session hook](../../apps/web/src/workspace/useNoteSession.ts) connects acknowledged metadata and combined dirty state without recreating the editor on saves. Explicit save buttons flush the same queue immediately. Autosave stops after a failure until an explicit retry or a new edit; revision conflicts and deleted notes stop writes until recovery. Disposal cancels pending timers/requests and ignores late results. Strict Mode effect replay reconnects the existing session before disposal.

When an unchanged body reattaches while a title/request is pending, the coordinator refreshes that body's comparison baseline. This prevents an editor instance's new schema identity from creating a phantom body edit and extra revision. A delayed-editor browser check holds a real SQLite title-save response while the editor mounts and verifies exactly one title-only write.

The [transition guard](../../apps/web/src/workspace/useNoteTransition.ts) flushes before note selection, workspace refresh, and lifecycle dialogs. It waits for an in-flight request and drains newer edits; a failed flush keeps the current note open. The latest requested destination wins while waiting. Lifecycle actions use the revision returned by the flush so an earlier save cannot race a rename, move, or deletion.

[Conflict recovery](../../apps/web/src/workspace/ConflictRecovery.tsx) offers a confirmed reload or saving local title/body as a new root note. Reload replaces the editor and its history only after a successful read. A native dialog warns before discarding local edits; cancel/failure keeps them. Copy creation keeps the original note unchanged and preserves the current source through the conversion boundary. An acknowledged copy is opened through refresh-only retry, avoiding duplicate creation after a failed metadata refresh. As with other create operations, an unacknowledged server commit cannot be deduplicated without API idempotency keys; retrying such a failed create may create another copy.

## Markdown and diagrams

Import stores the selected Markdown source verbatim within the input limits. Export flushes pending edits and downloads the latest saved Markdown without another parse/serialize cycle. Rich editor conversion runs in the frontend when loading or editing, and must preserve content outside the supported rich subset.

The [import dialog](../../apps/web/src/workspace/ImportDialog.tsx) opens through the transition guard, after saving pending writing. The destination is the selected folder or the active note's folder. Its editable title comes from the filename without `.md`, trimmed at the edges, with `Untitled` for an empty stem; invalid or long names require correction under the shared name rules. [File validation](../../apps/web/src/workspace/markdown-files.ts) checks the `.md` extension and shared 256 KiB import cap before reading, then decodes UTF-8 strictly with BOM retention and validates the complete source. The existing create API stores the source in one operation. Failed reads/requests retain the chosen file and title. An acknowledged creation retries only refresh/open, using the same operation lifecycle as other creates; unacknowledged creates retain the existing idempotency limitation.

The [export control](../../apps/web/src/workspace/ExportMarkdown.tsx) drains the note's save coordinator, including newer edits during an in-flight write. A failed flush reports an export error and keeps the draft without starting a download. Successful exports encode the acknowledged source directly to UTF-8 bytes and trigger a local Blob download. The filename is a single bounded `.md` name with path, control/direction characters, and Windows device names made safe. Temporary anchors and object URLs are released. [T12 evidence](../../roadmaps/initial-project.md#t12) records actual file-picker, download, fallback, hostile-source, and save-ordering verification.

The selected roadmap defines supported rich editing constructs and the fallback for other source. For the initial release, see [R6](../../roadmaps/initial-project.md#r6--import-and-export-markdown). Unsupported syntax stays in the saved Markdown; conversion must never silently remove it.

Render Mermaid asynchronously with unique diagram IDs and per-block request versions. Discard stale results after another edit or note switch, clean up temporary rendering elements, and preserve source on failure. Bound input/rendering complexity so pathological diagrams cannot monopolize the writing interface.

The [preview boundary](../../apps/web/src/editor/diagram-renderer.ts) uses pinned Mermaid 12.3.0 and DOMPurify 3.4.17. It lazy-loads Mermaid, serializes its global renderer, skips aborted queued work, removes temporary rendering DOM, suppresses global error diagrams, and returns fixed inline messages. [Preview policy](../../apps/web/src/editor/diagram-policy.ts) limits source to 16 KiB UTF-8 and 200 lines/semicolon statements, with Mermaid's 100-edge cap. Preview limits never truncate source or prevent saving it. Diagram configuration directives/frontmatter and external CSS are rejected; SVG output additionally removes HTML, executable content, links, and images. The [Mermaid API](https://mermaid.js.org/config/usage.html#api-usage) and [configuration schema](https://mermaid.js.org/config/schema-docs/config.html) define the library settings. [T10 evidence](../../roadmaps/initial-project.md#t10) records mounted editing, persistence, asynchronous cleanup, and hostile-source verification. Large Mermaid vendor chunks load lazily as local assets; production packaging remains T14.

Treat all Markdown as untrusted: keep raw HTML inert and unsafe link protocols non-executable in previews and editor views. New link controls reject unsafe protocols. Source preservation must not enable script execution. Initialize Mermaid with `securityLevel: 'strict'` and `startOnLoad: false`; disable diagram-supplied configuration overrides and arbitrary HTML labels.
