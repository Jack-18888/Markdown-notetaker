Track consequential choices below. Product-mandated stack constraints remain requirements, not choices awaiting validation.

- `proposed`: Intended choice, not yet implemented and checked for its stated scope. Link to the owning validation task; pending evidence is not proof.
- `validated`: Implemented and verified for an explicit scope. Link to implementation, tests, and dated evidence with commands, outcomes, environment, and limitations. A code link or completed task alone is insufficient.
- `superseded`: Replaced choice. Retain its rationale, replacement link, and consequences; record the replacement with its own status.

Update the owning row when evidence changes. If a material change invalidates a choice's verification, return it to `proposed` until rechecked and preserve earlier evidence as history. A validated choice does not certify other choices or the entire application. Architecture topics own current behavior; roadmaps own release acceptance and verification history.
